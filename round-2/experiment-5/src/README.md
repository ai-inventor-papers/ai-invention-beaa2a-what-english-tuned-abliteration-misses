# Utility cost and inner harm signal after abliteration: four checkpoints, English and Slovene

Iteration-2 artifact `gen_art_experiment_5` of run `run_Fapgmt6JWbcD` (plan `gen_plan_experiment_2_idx2`). It covers the
**four frozen core checkpoints**:

- `cjvt/GaMS3-12B-Instruct@1d0b27af` and its iteration-1 Heretic LoRA edit (trial 88)
- `google/gemma-3-12b-it@96b6f1ec` and its edit (trial 96)

Everything is measured in **English and Slovene** under one code path, NF4 4-bit precision, the same chat template and the
same system prompt. The work has seven parts:

1. utility (six lm-eval tasks, 250 frozen items per task and language) and FLORES+ NLL
2. held-out harmless divergence and output validity
3. layer-wise bilingual harm geometry
4. frozen versus refit probes before and after each edit
5. the pre-registered **A2** test (criterion shift versus evidence loss)
6. label-free S5/S5X projections for the next iteration
7. a bounded base-model diagnostic

It also adds two exploratory analyses (drift geometry and an edit-strength dose-response) that sharpen what survives.

Every number below is copied from `results/analysis/tables.md`. That file is generated by `report_tables.py` from the saved
result files and re-checked by `verify_numbers.py` (80/80 recomputations agree, see `results/verify_numbers.json`). `audit_headline.py` separately re-derives the judged refusal rates, both kappas, the dose R_seq shares and the utility macro deltas from the raw judge log, generations and per-item parquet (all identical), and runs placebos: permuted-judge kappa −0.06, checkpoint-shuffled refusal gap ≈ 0 (`results/audit_headline.json`).

## Main results (observations, then interpretation)

**Behaviour.** Refusal rates are from gpt-4.1 labels on held-out StrongREJECT twin prompts (S4), on a random half; see "Deviations".

| checkpoint | EN refused % [95% CI] | SL refused % [95% CI] |
|---|---|---|
| GaMS original | 100 [100, 100] | 100 [100, 100] |
| GaMS edit | 5.6 [2.4, 9.5] (complied 92.9) | 6.7 [3.0, 11.1] (complied 89.6) |
| Gemma original | 99.3 [97.8, 100] | 99.2 [97.6, 100] |
| Gemma edit | **70.3** [61.9, 78.0] | **95.3** [92.0, 98.7] |

- The English-derived GaMS edit transfers completely to Slovene. The Gemma edit barely changes Slovene behaviour, even
  though Gemma's EN/SL harm directions are *more* similar than GaMS's. The raw cosine at the primary site is 0.919 vs 0.832;
  corrected against the split-half noise ceiling it is 0.979 vs 0.890.
- **Direction cosine does not predict cross-language transfer of the edit.**
- The judge matters. The Heretic keyword rule says Gemma's edited English refusal rate is 32.7%, while gpt-4.1 says 70.3%:
  Gemma's "Okay, let's…" replies often only lecture. Agreement between the marker rule and gpt-4.1 has kappa 0.707. The
  second-family judge agrees with gpt-4.1 at kappa 0.828 (refused vs not, n = 200) and 0.765 (6-way).

**Utility and language ability.** No measurable damage in any of the four cells.

- Macro change (points, [95% CI]):
  - GaMS: EN +0.13 [−0.53, 0.80], SL +0.20 [−0.73, 1.13]
  - Gemma: EN +0.13 [−0.53, 0.80], SL 0.00 [−0.60, 0.60]
- Holm-adjusted p = 1.0 for all four tests in the confirmatory family.
- All 24 per-task changes lie within ±1.6 points.
- FLORES+ devtest NLL changes by at most 0.002 nats.
- 0% empty, ≤0.4% malformed, and 0% other-language replies on harmless twins. Only 2 of 257 GaMS-edit Slovene harmful
  replies switch to English.
- Harmless divergence (median KL, first token / 32 tokens):
  - GaMS: EN 0.044 / 0.023, SL 0.017 / 0.007
  - Gemma: EN 0.000 / 0.015, SL 0.011 / 0.004
- Gemma starts 255/257 English harmless answers with "Okay,". That makes first-token KL (and first-token R1) uninformative
  for Gemma EN; the 32-token KL is the meaningful number there.

**Harm information before the edit (original models).**

- Harmfulness is linearly decodable at the frozen iteration-1 sites (GaMS L34, Gemma L20, position −1, winsorized float32):
  - DiM trained on S3 dev, tested on held-out S4: 0.998 / 0.997 (GaMS EN/SL) and 0.997 / 0.996 (Gemma).
  - Held-out harm categories (hoc stratum): ≥ 0.989.
  - EN→SL and SL→EN transfer: ≥ 0.995.
- It is not lexical or length-driven:
  - TF-IDF baseline 0.81 on S3 and 0.63 on S4; prompt length alone 0.51–0.67.
  - Length-residualized DiM stays at 0.92–0.96.
  - The language-identity direction gives AUROC 0.54–0.55 for harm.
  - Shuffled-label placebo: 0.49 / 0.51.
- Iteration-1 cosines are reproduced (0.832 vs 0.83; 0.919 vs 0.92).

**What the edits do to the inner harm signal (frozen vs refit).**

- **GaMS:**
  - The frozen original DiM probe collapses on edited activations: S4 AUROC falls by 0.40 (EN) and 0.58 (SL) at L34, to a
    minimum of 0.20 at L27, below chance.
  - A probe refitted on the edited activations still reaches 0.985 (EN) and 0.954 (SL).
  - The refit loss is 3–7% of the frozen loss for DiM and 0% for the logistic probe.
  - Pre-registered classes: DRIFT for the logistic probe; INFO-LOSS for DiM, because its small refit drop has a CI that
    excludes 0.
  - Drift geometry (exploratory, `mech_extra.py`):
    - 71% (EN) and 73% (SL) of the harmful-minus-harmless mean-difference energy lies on the frozen axis before the edit;
      0.2% and 0.1% after.
    - Cohen's d on that axis goes 6.20→0.30 (EN) and 5.61→−0.18 (SL).
    - A probe with the frozen axis projected OUT keeps AUROC 0.985 (EN) and 0.955 (SL).
    - The refit harm axis rotates (cos 0.27 EN, 0.19 SL).
  - Collapse begins at layer 22 in both languages, the layer of the ablated direction.
  - So the edit removes the dominant harm axis; the remaining off-axis code still carries almost all the information.
    Most of what the frozen probe loses is re-encoding, not lost information.
- **Gemma:**
  - At its frozen primary site (L20) nothing changes (frozen and refit ΔAUROC ≤ 0.002). The trial-96 edit ablates a layer-26
    direction with weights peaking around layers 28–31.
  - From layer 28 the frozen-axis separation roughly halves, **equally in both languages**: Cohen's d 6.90→3.35 (EN) and
    6.10→3.23 (SL) at L28.
  - Yet behaviour changes only in English, so **compression of the harm axis does not explain Gemma's language asymmetry.**
  - Two quantities do differ by language:
    - The late-layer harm axis rotates more in English: cos(orig refit axis, edit refit axis) 0.53 EN vs 0.83 SL at L40.
    - Harmful items shift less along Heretic's direction in Slovene at L40–48: −1.49 SD EN vs −1.16/−0.89 SD SL.

**A2 (pre-registered): does the post-edit refusal readout still track the ORIGINAL harm evidence?**

- **GaMS.** R_seq passes the validity gate in both languages:
  - EN: item AUROC 0.989, 16-cell Spearman 0.867. SL: 0.995 / 0.899.
  - Slope ratio 0.359 [90% CI 0.325, 0.392] (EN) and 0.420 [0.341, 0.494] (SL); intercept shifts −0.84 and −0.75.
  - Pre-registered decision: **EVIDENCE_LOSS**, i.e. slope compression.
- **Gemma.** R_seq fails the gate in EN (item AUROC 0.804), so the pre-registered readout is the judged logistic, which also
  gives EVIDENCE_LOSS. The Gemma R_seq slope ratios are 0.61 (EN) and 0.48 (SL).
- Interpretation: together with the frozen/refit result, the evidence is a **changed mapping, not information loss**. The
  edited models still linearly encode harmfulness, but their refusal readout depends ~2–3× less on the original evidence axis.
- Caveats:
  - The pre-registered label "EVIDENCE_LOSS" names the slope compression, not a loss of representation.
  - The slope is dominated by the harmful-vs-harmless contrast. Within-harmful slopes are unresolvable (90% CIs span 0).
  - Judged-logistic ratios are inflated toward 0 because pre-edit refusal is almost perfectly separated.
- The s:post:lang interaction CI excludes 0 in both models (0.25 GaMS, 0.33 Gemma, R_seq scale), so the change is not
  language-invariant.

**Which items flip (exploratory).** Among Gemma harmful prompts refused by the original, the ones the edit flips to
compliance are those with *lower* original harm evidence. For gpt-4.1 labels in EN, the AUROC of s_frozen_orig for flipping
is 0.24 [0.11, 0.39]; for SL marker labels it is 0.24. That pattern is the signature of a moved decision threshold on a
preserved evidence axis. For GaMS almost everything flips (92–95%), so there is nothing to rank.

**Edit strength (exploratory dose-response, `dose.py`, LoRA delta × f).**

- GaMS: English and Slovene fall together. At f = 0.75, 20.8% / 12.5% marker refusals remain; at f = 1, none.
- Gemma: Slovene needs ~2× the strength English needs. Harmful prompts with R_seq > 0:

  | f | EN | SL |
  |---|---|---|
  | 1 | 90.3% | 98.8% |
  | 1.5 | 45.1% | 77.4% |
  | 2 | 24.5% | 46.3% |
  | 3 | 12.8% | 7.0% |

  Marker refusal on SL: 91.7% (f = 1), 68.8% (f = 1.5), 31.2% (f = 2), 8.3% (f = 3).
- At f = 3 the Gemma Slovene harmless first-token KL explodes (median 0.82).
- So the Gemma Slovene non-transfer is **partly an edit-strength effect**. Heretic's optimizer stopped at a weak,
  low-KL edit (KL 0.024 vs GaMS 0.175 on Heretic's own prompts; `README` of iteration-1 E1). Slovene refusal in Gemma is
  more robust to that edit, but not unreachable.
- Differences between the two models therefore mix intrinsic properties with *achieved optimization*; see "What this does
  NOT show".

**r_prior (harmless-refusal direction).**

- Defined in both models from second-judge-labelled r_prior generations:
  - GaMS: 36 refused (EN 15, SL 21).
  - Gemma: 55 refused, of which 47 are SL.
- Gemma's pooled r_prior is language-confounded: cos with the language direction at L20 is 0.62. The within-SL version
  (−0.14) is the interpretable one.
- Projections on it are stored for every S5/S5X row.

**Bonus: GaMS3-12B base** (`cjvt/GaMS3-12B@46127695`, raw "Question/Answer" format).

- Harm is decodable in the base: grouped-CV S4 AUROC 0.988 (EN) and 0.958 (SL) at L34.
- The base's own S3 direction transfers worse to S4: frozen AUROC 0.817 / 0.773, best 0.93 / 0.88 at L26.
- Its harm direction is nominally dissimilar to the Instruct one (cos 0.31, nominal coordinates only).
- gpt-4.1 labels 14/20 EN and 13/20 SL harmful continuations as complied. This is descriptive and **not** comparable to
  chat-model refusal rates.

## What this does NOT show

- Two models and one Heretic run each. There are no family-level or training-stage claims; Gemma-IT is a same-size
  reference, not GaMS's parent.
- Cross-model differences mix model properties with achieved optimization:
  - GaMS trial 88 uses a layer-22 direction with weights > 1 in almost all layers.
  - Gemma trial 96 uses a layer-26 direction whose down_proj weight decays to ~0.
- Probe AUROC shows linear decodability, not causal use.
- Slovene S4 prompts are machine translations with automated QC only; native review is pending.
- Judge labels come from gpt-4.1 on a random half of harmful generations plus a free second-family judge (kappa above).
  There are no human labels.
- The drift geometry, flip analysis and dose-response are exploratory, not confirmatory.

## Deviations from the plan (also in `method_out.json` → `metadata.deviations`)

- **D1** NF4 4-bit weights for all four checkpoints.
- **D2** 250 frozen stratified items per task and language (`configs/utility_sample_ids.json`, sha256 in the protocol).
- **D3** In-house harness-replica scorer, validated on the original models against lm-eval 0.4.13 (EN) and against
  GaMS-Team `tasks_sl@d05d470f` run in the same harness (SL).
  - Rendered prompts are 100% identical; correct-flag agreement is 98.7% (GaMS) and 99.5% (Gemma)
    (`results/<m>/harness_validation.json`).
  - The pre-registered |Δll| < 0.05 nats bar fails (median 0.10 GaMS, 0.13 Gemma), because lm-eval returns bf16-rounded log-likelihoods
    (e.g. −18.875) while the scorer is float32. This is numeric, not a template error.
- **D4** The validity gate uses item AUROC plus a condition-level Spearman.
- **D5** The A2 x-axis is the original-model frozen score.
- **D6** No human review. `results/native_review_packet_c1u.csv` is marked PENDING; its answer key is
  `…_KEY.csv`.
- **D7** Winsorization is the parameter-free per-vector q = 0.995 (iteration-1 recipe). The plan's per-dimension clip is a
  sensitivity analysis.
- **D8 Judge budget.**
  - The shared key was at its daily limit until 00:00 UTC.
  - The run-level budget ($7 for this phase, shared with sibling artifacts) was exhausted at 00:04 UTC, after this artifact
    had spent $1.11.
  - gpt-4.1 therefore labels a hash-ordered, effectively random 118–150 harmful generations per model × checkpoint ×
    language (1,072 in total), and none of the harmless or r_prior generations.
- **D9 Second judge.** `nvidia/nemotron-3-ultra-550b-a55b:free` replaces gemini-2.5-flash, since paid models were blocked;
  it stopped at the free-tier daily cap of 1,000 requests.
  - It labels 200 stratified items for kappa, all 376 r_prior generations, and ~50 harmless generations per model ×
    checkpoint.
  - The gate and the judged A2 use combined labels: gpt-4.1 where available, otherwise the second judge.
- **D10** Harmless generations exist for all 257 twins at 128 tokens (a superset of the planned 100-item sample, H100).
  Rule-based validity covers all 257.
- **D11** The interrupted first session ran on an L4 and this session on an RTX 4090; both are sm_89 (`env/gpu.txt`).
  Every paired original-vs-edited quantity was computed in one session with one model load, the adapter toggled.
- **D12** Exploratory additions: `mech_extra.py`, the flip analysis, `dose.py`, and `dose_judge.py`. The last was prepared
  but not run, because the free-tier cap was reached.
- **Split access.** Each S7 file was read 6 times (`logs/split_access.log`): the protocol freeze, mini tests, one GaMS run
  killed before writing any utility output, its resumed run, and Gemma. Each checkpoint's final utility scores were
  written exactly once.

## How to run

```bash
uv venv .venv --python=3.12
uv pip install --python .venv/bin/python torch==2.11.0+cu128 torchvision==0.26.0+cu128 --index-url https://download.pytorch.org/whl/cu128
uv pip install --python .venv/bin/python -r pyproject.toml     # exact versions: env/requirements.lock
export NUMPY_MADVISE_HUGEPAGE=0     # see common.py: THP compaction stalls big numpy allocations on these hosts
.venv/bin/python freeze_protocol.py
.venv/bin/python method.py --model gams  --stages check,gen,acts,kl,hval,util,flores,s5acts,rseq
.venv/bin/python method.py --model gemma --stages check,gen,acts,kl,hval,util,flores,s5acts,rseq
.venv/bin/python mech.py --model gams && .venv/bin/python mech.py --model gemma
.venv/bin/python mech_extra.py --model gams && .venv/bin/python mech_extra.py --model gemma
.venv/bin/python judge.py --wait-for-key 240 --second       # needs OPENROUTER_API_KEY / OPENROUTER_BASE_URL
.venv/bin/python readouts.py --source judge && .venv/bin/python method.py --model gams --stages rseq && .venv/bin/python method.py --model gemma --stages rseq
.venv/bin/python analyze.py && .venv/bin/python report_tables.py && .venv/bin/python figures.py
.venv/bin/python review_packet.py && .venv/bin/python verify_numbers.py && .venv/bin/python build_output.py
# exploratory / bonus
.venv/bin/python dose.py --model gemma && .venv/bin/python dose.py --model gams && .venv/bin/python base_diag.py
```

Model weights live in the run's shared Hugging Face cache (pinned revisions above). Adapters, directions and data are read
in place from the iteration-1 workspaces (`common.py`: `E1`, `E3`, `DS`).

## Restoring removed files

The full float32 residual captures `acts/<m>/{S3,S4}_{orig,edit}.npy` and `acts/<m>/S5_orig.npy` (~24 GB, 2.2–3.0 GB per
file) and the mini-run captures `acts_mini/` were **deleted after the analysis** (GitHub 100 MB file limit). Every result
file was produced before deletion, and `analyze.py` was re-run afterwards with an identical `summary.json`. It reads
`acts_primary/` (kept: primary-layer slices, each < 100 MB) and the cached `results/<m>/r_prior_<m>.{json,npz}`.

To recompute the all-layer profiles (`mech.py`, `mech_extra.py`), r_prior, or the S5 projections, regenerate the caches
(about 10 GPU-min per model, NF4). The stage files are deterministic up to GPU numerics:

```bash
.venv/bin/python method.py --model gams  --stages acts,s5acts
.venv/bin/python method.py --model gemma --stages acts,s5acts
.venv/bin/python method.py --model gams --mini --stages check,gen,acts,kl,util,flores,s5acts,rseq   # acts_mini/ (T1 smoke test)
```

`mech.py` and `mech_extra.py` stop with this command in the error message if `acts/` is absent (`common.need_acts`).

- `.venv/`: rebuild with the `uv` commands in "How to run" (exact pins in `pyproject.toml` / `env/requirements.lock`).
- `__pycache__/` and `third_party/sleval_tasks_tree/sl_winogrande/__pycache__/` are recreated on import (the latter when lm-eval loads the Slovene tasks in `method.py --stages hval`).
